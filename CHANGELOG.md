# Changelog

Notable changes to Summer Code. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

While the version is below `0.1.0` the public API of every crate should be read as unstable.

## [Unreleased]

### Security

- `web_fetch` and `web_search` no longer let their HTTP client resolve a hostname for itself. The host was authorized by the broker and then looked up a second time by `reqwest`, and nothing made the two answers agree: a poisoned cache, a hostile resolver, or a short TTL and a cooperative authoritative server was enough for the bytes to move to an address the policy never evaluated. `Broker::lookup` now resolves the host inside the same evaluation that prompts, remembers, and journals it, and both tools build their client over a resolver that replays only those addresses and refuses every name it was not given. A URL with an IP-literal host is unaffected, since there is no lookup to disagree with. Two smaller consequences ride along: a redirect off the search endpoint to an unauthorized host now fails instead of being followed, and each fetch opens one TCP connection instead of two, since the broker used to connect and drop a socket the tool never read.
- A `Permission` record for an outbound connect now carries the addresses the host resolved to, and a new `inward-resolution` runtime property flags an **allowed** connect whose named host resolved to loopback, link-local, or the unspecified address. Network rules match hosts by name, so `allow docs.example.com` says nothing about where that name points: a resolver answering `127.0.0.1` turns an approved documentation fetch into a request against whatever is running locally, and `169.254.169.254` turns it into a cloud credential read, with no second prompt because the address was never part of the question. The broker cannot refuse these without overruling a rule the user wrote, so the monitor reports them instead, in the journal and in the transcript. `localhost` and `*.localhost` by name are not flagged, nor are address literals (nothing resolved) or private ranges (split-horizon DNS is ordinary practice).
- Proxies are off for both web tools. An `HTTP_PROXY` in the environment sent every request to a host the policy never saw, with the authorized host demoted to a request line, so the check the tool reported was not the connection it made. A proxied setup now fails closed; honouring one would mean authorizing the proxy through the broker.
- The kernel-confinement exec auto-allow now requires the backend to report **both** path and outbound-connect enforcement, where it previously required only paths. Auto-allowing a command hands the Landlock domain to a child process whose `connect` never reaches the broker, so the broker's own network prompt was no protection against it; the only thing governing that child's egress is Landlock's `ConnectTcp` rule, and that rule is absent whenever a policy names a host without a port. That combination left `connect` at `Partial`, `paths` at `Enforced`, and every unlisted command auto-running with unrestricted egress behind it. Sessions without `--sandbox` were unaffected, since confinement is opt-in and the auto-allow never applied to them.

### Added

- Integration tests for the headless contract (`crates/cli/tests/headless.rs`), the first tests in `cli` to run the real binary. `cli` carried 19.8k lines and 280 unit tests with nothing covering the interface programs actually use: the exit code per stop reason, which stream each line goes to, the field names in the `json` result object, and the promise that `stream-json` is newline-delimited with exactly one `result` object to be found by `kind` rather than by position. One test pins the ordering `main` documents, that arguments are parsed before anything opens a journal, so a mistyped flag leaves no session directory behind. No model is reached: each run is isolated from the developer's credentials and home directory, so the turn fails locally on "no credential", which is the documented behaviour and reaches the same reporting code a real stop reason does.
- Property-based tests for the policy evaluator (`crates/policy/tests/evaluator_properties.rs`), covering containment in both directions, the protected-directory write denies at arbitrary depth, root dotfiles, and the two fail-open shapes the evaluator documents: a host deny dodged by case or a trailing dot, and a command deny dodged by naming a path to the program. `proptest` had been a declared dependency with a comment claiming it covered the tool-argument validator and no use anywhere in the workspace.
- Property-based tests for the tool-argument validator, the use that comment had been claiming. One property asserts it answers rather than panics for arbitrary arguments against arbitrary schemas, since both sides are untrusted: the arguments come from the model and a schema can come from an MCP server this build has never seen. The other walks the built-in registry, so a tool added later is covered without anyone remembering to add it, and asserts that a call with every declared property filled validates, that dropping a required property is refused *by name* (the message is what the model reads to correct itself), and that dropping an optional one still validates.
- The benchmark task set grows from 6 tasks to 24, in six groups (`smoke`, `compile`, `multistep`, `skill`, `navigate`, `precise`), with six new fixtures. At 6 tasks the ablation matrix could not separate a mechanism from noise unless it dropped the pass rate by 36 points, which made `make ablate` guaranteed to report "not enough evidence" for every arm it costs 180 model sessions to produce. The total row now resolves a 15-point effect at the default `RUNS=5`.
- Tasks carry a `group`, and the ablation matrix pools each group's runs into its own row. A mechanism only changes the outcome of tasks that reach it, so its effect arrives diluted across the whole set; the group row is where those runs are counted together instead.
- Continuous integration on pull requests: the `make check` gate, an MSRV check, and native macOS and Windows test runs. Deliberately not wired to `push`, so a direct commit to `main` stays gated by the local run alone; see `AGENTS.md` for the reasoning.
- `SECURITY.md`, with the threat model, private reporting instructions, and an explicit out-of-scope list.
- This changelog.

### Changed

- The journal's unit of record is `journal::Record`, renamed from `Event`, with `RecordKind`, `RecordId`, `read_records`, `write_record(s)`, and `Journal::from_records` following it, and the prose in `journal`, `engine`, `sandbox`, `README.md`, `SECURITY.md`, and `docs/` following those. Three other types in the workspace are events and none is durable: `engine::UiEvent` is a frame for the screen, `provider::StreamEvent` a chunk off the wire, crossterm's `Event` a keystroke. Naming the durable one for what it is leaves the bare word to the transient meanings. One adjacency comes with it: `sandbox::PermissionRecord` is the broker's decision and *becomes* a `Record`, and where the two meet (`Engine::drain_permissions`) the broker's side is now named `decided` so `record` keeps one meaning.
- `Folded.events` is `Folded.records` on the wire as well as in Rust, which is the rename's only wire-visible consequence. The old spelling is accepted on read (`#[serde(alias = "events")]`), because dropping it would make any session that had folded a subagent unresumable; new journals write `records`. An older build reading a newer journal is the case this does not cover, and the schema version is unchanged because nothing else about the format moved.
- Lints live in `[workspace.lints]` and are inherited by every crate, where before `-D warnings` in the Makefile and in CI was the only thing that said anything about them. That flag decides severity and cannot name a lint, so any lint outside the default groups had nowhere to live, and a plain `cargo clippy` or an editor's rust-analyzer ran a different set from the gate. Three placeholder lints (`clippy::dbg_macro`, `clippy::todo`, `clippy::unimplemented`) and `unsafe_code` are now denied in the manifest: the workspace had no instance of any of them, so this denies a regression rather than a habit. `sandbox` (the Landlock ABI probe and `openat2`), `cli` (`env::set_var`, unsafe as of edition 2024) and two `sandbox` test binaries carry a documented crate-root `#![allow(unsafe_code)]`, which is the same reviewable-exemption shape `clippy::disallowed_methods` already used.
- `sandbox::PermissionRecord` carries `supplied: Supplied` in place of `bound: Option<IpAddr>`. Two dimensions need the broker to contribute a fact the request does not hold, and they need different shapes: a listen's bound address, and a connect's resolved addresses. One `Option<IpAddr>` could only carry the first.
- A failed `web_fetch` or `web_search` request reports its cause chain rather than `reqwest`'s top-level message alone. "error sending request for url (...)" named the URL the model already knew and nothing about what went wrong, which for a refused host or a TLS failure is the entire content of the answer.

- `docs/REVIEW.md` and `docs/REVIEW-2.md` moved to `docs/archive/`, each with a header marking it superseded. Both were point-in-time audits whose findings had all been fixed, and both read as live defect reports where they sat.

### Removed

- `engine::daemon`, a session registry no frontend ever connected to.
- `query::embed` (`Embedder`, `NullEmbedder`, `EmbedError`), a trait whose only implementation reported embeddings as disabled and whose only caller was the ablation example's demonstration of that fact. The example now compares grep against facts, which are the mechanisms the project actually ships.

### Fixed

- The bench runner no longer copies `target/`, `__pycache__/`, `node_modules/`, or `.git/` into a run's tree. `std::fs::copy` stamps every destination with the time of the copy, so a leftover `target/` arrived with artifacts no older than the sources beside it and cargo read the stale build as fresh: the run then executed a binary compiled from whatever the fixture held when someone last checked the task by hand, which for a solved task is the solution. The criterion passed, the agent did nothing, and the cell was indistinguishable from an earned one.
- `--allow-unenforced` was documented across the Makefile, six source files, and the bench harness as a flag a user could pass. The CLI has never parsed it; the remedy it named is to run without `--sandbox`, and every reference now says so.
- `scripts/check-platforms.sh` listed `summer-monitor` and `mcp` among the crates to fall back to, and neither has ever been a workspace member, so the fallback path could only error.
- The MSRV comment in `rust-toolchain.toml` claimed 1.85 while `Cargo.toml` declared 1.88. The declared value is now verified by CI.
