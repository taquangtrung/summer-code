# Summer Code Codebase Review

> **Archived, and superseded.** This is a point-in-time audit taken on 2026-08-06, kept for the reasoning it records rather than as a description of the code. Every defect it names has since been fixed, and the commit it cites no longer exists in this repository's history. Read [`docs/ARCHITECTURE.md`](../ARCHITECTURE.md) for what the system does now and [`docs/ROADMAP.md`](../ROADMAP.md) for what is planned.

A review of the current codebase against one goal: making **Summer Code** produce well-structured, modular, high-quality code while running on cheap models (Gemini Flash, Haiku, DeepSeek), at a quality level competitive with Claude Code and Codex.

Reviewed at commit `23ab45a` (`feat: support keybindings`) on 2026-08-06. Findings were verified by reading the crates and by running `cargo check --workspace`.

## Summary

The infrastructure is strong: event-sourced journaling with exact replay, kernel-enforced sandboxing, a policy engine with an adversarial test suite, and a benchmark harness that reports Wilson intervals rather than bare percentages. The layer that actually governs code quality is the weak part. Phase 8 shipped four mechanisms for cheap-model quality, and three of them have zero callers, so they have no effect on a real run.

The single largest quality gap is the `edit` tool, which overwrites whole files. That primitive is the main reason a cheap model here produces worse code than the same model would under Claude Code or Codex.

## What is working well

* **Journal and replay.** Every turn, tool call, and permission decision is an immutable JSONL event, and a session replays or resumes with exact state restoration. Very few agents get this right.
* **Zero-trust policy and kernel sandbox.** Landlock confinement on Linux behind a broker typestate, with path traversal, symlink escape, and command injection covered by tests.
* **Provider resilience.** Exponential backoff with full jitter, `Retry-After` parsing, and mid-stream failure recovery that discards dead attempts.
* **Statistically honest benchmarking.** [`crates/bench/src/score.rs`](../../crates/bench/src/score.rs) reports a rate with its 95% Wilson interval and a `distinguishable` flag, so a change that is noise cannot be read as an improvement.
* **Rationale comments.** Files such as [`crates/engine/src/prompt.rs`](../../crates/engine/src/prompt.rs) and [`crates/tools/src/dispatch.rs`](../../crates/tools/src/dispatch.rs) explain why a decision was made, not just what the code does.

## Finding 1: the cheap-model layer is not connected

`docs/PROGRESS.md` lists Phase 8 as complete, but the mechanisms are unreachable from a live session.

| Built | Location | Callers |
|---|---|---|
| `extract_skeleton` (257 lines) | `crates/query/src/skeleton.rs` | 0 |
| `CHEAP_MODEL_SYSTEM_PROMPT` | `crates/engine/src/prompt.rs` | 0 |
| `LspExtractor` (213 lines) | `crates/query/src/extract/lsp.rs` | not exposed as a tool |
| `load_rules`, `format_user_rules` | `crates/cli/src/rules.rs` | 0 |
| `KeybindingRule` and loaders | `crates/cli/src/keybindings.rs` | 0 |

`crates/cli/src/main.rs:496` always selects `SYSTEM_PROMPT`, so the cheap-model prompt never reaches a provider. Nothing routes a `read` through the skeleton extractor, so context distillation never happens. `cargo check --workspace` already reports the CLI cases as dead code:

```text
crates/cli/src/rules.rs:16:8: warning: function `load_rules` is never used
crates/cli/src/keybindings.rs:44:12: warning: associated items `new`, `bind`, `parse_json`, and `load_from_dir` are never used
```

This is the cheapest fix on the list, and it is a prerequisite for measuring anything else.

## Finding 2: whole-file overwrite is the wrong edit primitive

`crates/tools/tools/edit.json` describes the tool as replacing the entire file:

```text
Overwrite a file with the given content. This replaces the whole file, so read it
first and send back its complete new contents; anything you leave out is deleted.
```

Four consequences, each of which hits cheap models hardest:

* **Cost.** A 400-line file costs roughly 5k output tokens per edit. Output tokens are the expensive ones, so this dominates the bill and removes the economic reason to use a cheap model at all.
* **Silent truncation.** Emitting `// ... rest unchanged` is the canonical Flash and Haiku failure mode, and under this tool it deletes the body of the file rather than being a harmless annotation.
* **No staleness check.** Nothing verifies that the model read the current version before overwriting it, so a stale read silently clobbers intervening work.
* **Unrequested churn.** Regenerating untouched code is exactly the moment a model reformats and restructures things the task never asked about, which is the opposite of the "minimal blast radius" rule the prompt states.

Claude Code and Codex both use anchored string replacement for these reasons. Replacing this one tool will improve output quality more than every other item in this document combined.

## Finding 3: verification advises rather than gates

[`crates/engine/src/engine/mod.rs:754`](../../crates/engine/src/engine/mod.rs) runs `verify_code_edits` after every `edit` call and appends the diagnostics to the tool result as text. Three problems:

* It runs a full workspace `cargo check` per individual edit, with no debounce.
* It runs inside `dispatch_one`, outside the `Dispatcher` timeout, so it has no wall-clock cap at all.
* The result is a suggestion. Nothing stops a turn from ending on a tree that does not compile.

The substring filter in [`crates/tools/src/verifier.rs`](../../crates/tools/src/verifier.rs) also matches on `error:`, which catches non-diagnostic noise such as `error: could not compile`.

## Finding 4: the `symbols` tool is not an AST parser

[`crates/tools/src/builtin.rs`](../../crates/tools/src/builtin.rs) implements symbol extraction with a line-prefix table (`("fn ", AstNodeKind::Function)` and similar). This misclassifies multi-line signatures, generic bounds spanning lines, macro-generated items, and any occurrence inside a string or comment. Since the whole cheap-model strategy rests on giving the model precise structural context instead of raw text, the precision of this layer sets the ceiling on everything above it. `LspExtractor` already exists and is exact; it should back this tool.

## Finding 5: no planning or decomposition scaffolding

There is no task list, no plan state, and no subagent. Cheap models drift on multi-step work, which is the largest remaining structural failure mode after the edit primitive. Claude Code's todo state and subagent dispatch are a substantial part of why its output holds together across a long task.

## Finding 6: the benchmark cannot measure structure

`Success` in [`crates/bench/src/task.rs`](../../crates/bench/src/task.rs) is either `CommandExitsZero` or `FileMatches`. Both are pass/fail correctness oracles. A claim of "better structured than Claude Code" cannot be supported by a correctness oracle, because badly structured code passes tests.

## Recommendations

Ordered by leverage. Items 1 and 2 are where the quality difference actually lives.

### 1. Replace `edit` with anchored operations

Three operations behind one tool in `crates/tools/src/builtin.rs` and `crates/tools/tools/edit.json`:

* `create`: new file, fails if the path exists.
* `str_replace`: takes `old_string` and `new_string`, and fails if `old_string` does not match **exactly once**, with an error naming the ambiguity.
* `insert`: at a named anchor.

Add a read ledger to `ToolCx` so a `str_replace` against a file not read in this session returns `Outcome::Err` telling the model to read first. Return a unified diff as the `Outcome::Ok` content instead of `wrote N bytes`, so the model observes what it actually did.

The uniqueness constraint is the quality mechanism, not a safety detail: it forces the model to gather enough surrounding context to be unambiguous, which is precisely the discipline cheap models lack.

### 2. Make verification a blocking gate

* Debounce: run diagnostics once when the model stops calling `edit`, not per call.
* Scope diagnostics to the touched files, and drop the `error:` substring match.
* Add a turn-completion gate: before `Stop::EndTurn`, run format, lint, and the project test command. On failure, inject the output and force another turn. Cap the attempts, then surface the failure honestly rather than hiding it.

A cheap model that *cannot* end a turn on a broken tree beats an expensive model that merely tries not to.

### 3. Wire up what already exists

Select `CHEAP_MODEL_SYSTEM_PROMPT` from the provider profile in `crates/cli/src/main.rs`. Add a `mode: "skeleton"` argument to `read` that routes through `extract_skeleton`. Expose `LspExtractor` as `definition` and `references` tools, and back `symbols` with it. Call `load_rules` at session start.

The exact reference set from `rust-analyzer` is the specific thing that stops a cheap model from writing a helper that already exists three modules over.

### 4. Move judgment out of the model

This is the strategic point. Cheap models fail at judgment, not at typing. Every judgment call converted into a deterministic constraint or a retrieval result is quality obtained at cheap-model prices.

* **Router.** Strong model plans and reviews; cheap model executes each well-specified step. This is the concrete way to beat Claude Code on cost and quality at once, since Claude Code uses one model for both roles.
* **Structural budgets.** Encode maximum function length, cognitive complexity, and documentation requirements in `clippy.toml`, and hold the agent accountable to them through the gate from recommendation 2.
* **Anti-duplication check.** Before an edit that introduces a new function, query `symbols` or the LSP for a similar name and inject any hits into the tool result. "Audit before re-inventing" is a suggestion in the prompt today; this makes it a mechanism.
* **Per-directory rules discovery.** Extend `crates/cli/src/rules.rs` to walk upward from the edited file, collecting and injecting only the rules files relevant to that subtree. Repo-local convention is what makes generated code look like it belongs.

### 5. Add planning scaffolding

A `plan` tool that writes a step list, re-injected into context each turn, plus a `Stop::PlanIncomplete` variant so a turn cannot end with steps outstanding.

### 6. Extend the benchmark to measure quality

Add a `Quality` scorer alongside `Success`, recording:

* lint warning delta against the baseline
* diff churn: lines touched against the minimum needed
* duplicate symbol count
* dead code count
* an LLM-judge rubric with a strong model scoring the cheap model's output

Then run Claude Code and Codex over the same task set as baselines. The Wilson interval machinery in `crates/bench/src/score.rs` already answers "is this distinguishable from noise" correctly, so the only missing piece is the metric.

## Suggested sequence

1. Anchored `edit`, read ledger, diff output
2. Turn-completion verification gate
3. Wire skeleton, cheap prompt, LSP, and rules
4. Quality metrics in `bench`, plus a Claude Code baseline
5. Planning tool and the strong/cheap router
6. Anti-duplication check and structural budgets

Item 4 belongs before items 5 and 6 so that the later tuning runs against a number rather than a hunch.

## A note on the target

Beating Claude Code and Codex on raw code quality is hard, because a cheap model's ceiling on novel design is genuinely lower and no harness fully compensates for that. What is realistically winnable, and what this architecture is well suited for, is being **better on constrained, well-specified edits at a fraction of the cost**: correct diffs, no dead code, no duplication, no silent truncation, and an always-green tree. That covers most real work, and it is a claim the extended benchmark can actually substantiate.
