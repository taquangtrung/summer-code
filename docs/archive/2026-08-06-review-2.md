# Summer Code Codebase Review, Second Pass

> **Archived, and superseded.** This is a point-in-time audit taken on 2026-08-06, kept for the reasoning it records rather than as a description of the code. Its headline findings (the Python verifier, the replay contract, the no-op mechanisms) were all fixed in the work that followed, and the commit it cites no longer exists in this repository's history. Read [`docs/ARCHITECTURE.md`](../ARCHITECTURE.md) for what the system does now and [`docs/ROADMAP.md`](../ROADMAP.md) for what is planned.

A follow-up to [`REVIEW.md`](2026-08-06-review-1.md), covering the work that landed in response to it and answering one question: what to implement next to make **Summer Code** a top-class coding agent.

Reviewed at commit `9289f08` (`feat: support planning`) plus the uncommitted working tree, on 2026-08-06. Findings were verified by reading the diffs and by executing the commands the verifier runs.

## Summary

Recommendations 1, 2, 3, and part of 4 from the first review were implemented quickly. The `edit` tool now has anchored `str_replace`, `read` supports skeleton mode, a compilation gate runs before a turn ends, and a `plan` tool exists. That is good velocity.

The implementations have defects that matter more than the features are worth. One is a hard failure that makes Python projects unusable. One silently breaks the replay contract that the architecture document treats as a core guarantee. Two are no-ops or close to it. So the honest answer to "what next" is: fix what just landed, then stop adding mechanisms and build the measurement loop, because there are now five quality mechanisms in the tree with zero evidence that any of them help.

## Finding 1: the Python verifier bricks Python projects

`verify_python` in [`crates/tools/src/verifier.rs`](../../crates/tools/src/verifier.rs) invokes `python3 -m py_compile` with no filename arguments. Executed directly:

```text
py_compile.py: error: the following arguments are required: filenames
no-args exit: 2
```

The error filter tests `line.contains("Error:")` with a capital E, so it does not match the lowercase `error:` in that message. `errors` stays empty, the process did not succeed, and stderr is non-empty, so the `!output.success() && errors.is_empty()` fallback pushes the argparse usage text in as a diagnostic.

Combined with the new gate at `crates/engine/src/engine.rs:554`, this means **every edit turn in a Python project is blocked by a usage error the model cannot possibly fix**. The verifier needs the touched file paths passed through, or better, should call `ruff check`.

## Finding 2: the verification gate breaks the replay contract

The gate at `crates/engine/src/engine.rs:552` pushes a synthetic user message into live history without journaling it:

```rust
self.history.push(HistoryEntry {
    entry: Entry::User(format!("COMPILATION VERIFICATION GATE FAILED...")),
    ids: vec![],
});
```

There is no `self.record(...)` call and `ids` is empty. Core architectural contract 2 in [`ARCHITECTURE.md`](../ARCHITECTURE.md) states that every turn, tool call, tool result, and permission decision is recorded as an immutable event, and that any session replays with exact state restoration. This message exists only in memory, so **a resumed session diverges from the session that produced it** as soon as the gate fires. The golden journal suite will not catch it, because no fixture currently reaches the gate.

The gate needs its own `EventKind` so the injected feedback is part of the log like every other entry.

Two further problems with the same block:

* `has_edits = false` is assigned *before* the diagnostic check, so the gate fires at most once. A model that replies with prose and no further `edit` call exits cleanly on a tree that does not compile.
* `verify_code_edits` runs both per `edit` call (`crates/engine/src/engine.rs:774`) and again at the gate, with no debounce and no wall-clock cap. A turn containing six edits runs seven full workspace `cargo check` invocations.

## Finding 3: the anti-duplication check is likely net negative

`check_anti_duplication` in [`crates/tools/src/builtin.rs`](../../crates/tools/src/builtin.rs) calls `scan_dir_symbols` across the entire workspace once per symbol parsed out of `new_string`, on every `str_replace`. An edit introducing four functions triggers four full recursive tree walks, each reading every source file.

Cost aside, the `node.name.len() < 4` filter still admits `load`, `spec`, `call`, `next`, and `read`, so the check will report that those names already exist somewhere else essentially always. The codebase already articulates why this is harmful, at `crates/tools/src/builtin.rs:835`:

```text
// The common case. A marker here would train the model to ignore it.
```

False-positive warnings train the model to ignore every warning, including the true diagnostics from the verifier. This should require an exact signature match, or be removed until the benchmark can demonstrate it helps.

## Finding 4: the `plan` tool does nothing

[`crates/tools/src/plan.rs`](../../crates/tools/src/plan.rs) formats its own input back to the caller and returns. The `let _ = cx;` line is the tell. No state is stored, nothing is re-injected on subsequent rounds, no step survives into the next turn, and nothing prevents a turn from ending with steps outstanding.

The effect is that the model writes a plan once and then forgets it, which is not drift prevention. Plan state has to live in `Engine` and be re-injected each round for the tool to do anything at all.

## Finding 5: smaller defects

* `edit` still defaults to `overwrite` when `old_string` is absent, so the lazy path remains the destructive path. `overwrite` should require an explicit `action`, and the fallback should be an error pointing at `str_replace`.
* The `create` branch tests `full.exists()`, a raw stat that bypasses `cx.broker` while every other path in the file goes through it. Under Landlock confinement that can return `false` for a path that exists but cannot be stat-ed, at which point `create` clobbers a real file. It is also invisible to the audit trail.
* `load_rules`, `load_subtree_rules`, and `load_language_rules` in [`crates/cli/src/rules.rs`](../../crates/cli/src/rules.rs) still have zero callers outside their own tests.
* `load_language_rules` hardcodes "Never use `.unwrap()` or `.expect()` in non-test production code", while this codebase deliberately uses forms such as `.expect("head set by the ToolCall record")` as documented invariant assertions. Injecting a rule the repository itself violates teaches the model to fight local convention. Deriving rules from `clippy.toml` would be both accurate and self-maintaining.

## What to implement next

The core recommendation is to stop adding mechanisms and build the measurement loop.

There are now five quality mechanisms in the tree: skeleton reads, anchored edits, the compilation gate, anti-duplication, and the plan tool. None has evidence behind it, and findings 1, 3, and 4 suggest at least two are neutral or worse. `bench` still scores only `CommandExitsZero` and `FileMatches`, neither of which can observe structure. Until that changes, every additional feature is a guess, and the project has no way to notice when a guess is wrong.

### Priority order

1. **Fix the Python verifier and journal the gate event.** Both are correctness bugs in shipped code and both are small.
2. **Add quality metrics to `bench`,** with Claude Code and Codex baselines over the same task set: lint warning delta, diff churn against the minimum necessary change, duplicate symbol count, dead code count, and a strong-model judge rubric. The Wilson interval machinery in `crates/bench/src/score.rs` already answers "is this distinguishable from noise" correctly, so only the metric is missing.
3. **Ablate the five existing mechanisms.** Run the task set with each one disabled. Expect to delete at least one.
4. **Make `plan` stateful:** plan state held in `Engine`, re-injected each round, with a `Stop::PlanIncomplete` variant so a turn cannot end with steps outstanding.
5. **Add subagents with isolated context.** This is the largest remaining architectural gap against Claude Code and Codex. Dispatching a question such as "find every caller of X" into a sub-context and returning only the conclusion is what keeps the main context clean across a long task. It also fits the strong and cheap router directly: cheap models handle the fan-out, the strong model synthesizes.
6. **Add parallel tool dispatch.** [`crates/tools/src/dispatch.rs`](../../crates/tools/src/dispatch.rs) is deliberately serial, and documents why: journal append order is fully determined by the turn. Reads are independent and dominate call volume, so the latency and cost win is real, but the design must preserve determinism by ordering a completed batch on request index rather than completion order.

### Lower priority capability gaps

* A web search and documentation fetch tool, for live library and API reference lookup.
* LSP-backed `references` and `rename` exposed as tools, not just as fact extractors.
* A checkpoint and undo surface, so a user can reject an agent turn wholesale rather than unpicking it by hand.

## Relationship to the first review

Items 1, 2, 3, and part of 4 from [`REVIEW.md`](2026-08-06-review-1.md) are addressed in code, with the defects above.
